# 流程蒸馏

把刚完成的复杂任务提炼成可复用的工作流。默认产物是两份文件：`TASK_任务说明.md` 和 `CHECKS_检查清单.md`。只有明确要求、或这个流程已经稳定重复时，才再写一份 `SKILL.md`。

## 什么时候用

只在明确要求时：

- “把刚才这轮沉淀成工作流／技能草案。”
- “把这套做法写成 TASK 和 CHECKS。”

普通的复杂任务、代码收尾、研究汇报，不会自动触发。觉得“这好像可以复用”只是一个内部想法，不是去做的理由。

## 证据范围

可以用：当前对话里出现过的目标、步骤、失败与修正、验证结果、输出位置；需求方明确给出的文件；本次任务实际改过的文件；已有工作流文件的标题和开头部分（用于判断有没有相近的）。

不用：没点名的知识库和归档、完整聊天记录转储、账号与凭据、外部网络和第三方仓库。

## 更新旧的，还是新建？

1. 用一句话概括任务类型：对象、动作、产出、验证方式。
2. 在已有工作流里窄范围匹配（只看标题和开头）。
3. 已有工作流覆盖同类输入、工具和产出，只缺这次的新步骤或检查项：补丁式更新旧的。
4. 没有相近的，或目标不同：按“中文_English”命名新建。
5. 只能判断“可能相近”：列出 1–2 个候选和差异，请需求方决定。

## 生成步骤

1. 列出可复用的骨架：触发场景、输入材料、关键步骤、验证方式、清理动作、边界。
2. 删掉一次性细节：临时路径、过程吐槽、没验证的猜测、原始聊天片段。
3. 写 TASK：目标、触发与不触发、证据范围、步骤、产物、汇报格式。
4. 写 CHECKS：执行前边界、证据覆盖、输出结构、禁止事项、验证方式、失败处理。
5. 需要技能文件时只写最小的 `SKILL.md`：清楚的触发语和反触发条件，正文引用 TASK／CHECKS，加少量硬边界，不把整个流程复制进去。
6. 本地检查：文件存在、头部信息正确、路径有效、没有敏感信息、触发条件不会过宽。

## 禁止

- 粘贴完整聊天记录。
- 把临时调试结论写成长期规则。
- 照搬外部技能的路径、团队假设或安装步骤。
- 额外创建 README、安装说明、示例库或自动化脚本（除非单独要求）。

## 信息不够时

停下，只问 1–2 个具体问题，不写草案。

## TASK 模板

```markdown
# 流程名_Workflow Name

## 目标
## 触发 / 不触发
## 输入与证据范围
## 步骤
1.
2.
## 产物
## 汇报格式
```

## CHECKS 模板

```markdown
# 流程名检查清单

## 执行前边界
- [ ]
## 证据覆盖
- [ ]
## 输出
- [ ]
## 禁止事项
- [ ]
## 验证与失败处理
- [ ]
```
