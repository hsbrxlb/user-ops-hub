# 用户声音转化流程

一条评论只是一条线索。经过人工核对、聚类、确认之后，它才能成为能指导工作的认知。

## 什么时候用

- 把一批社区帖子、视频评论、产品评价或客服记录导入，整理成用户声音。
- 聚类已核对的观察，生成本周的用户声音报告。

不用于写普通文案、公开回复、外联或自动发帖。

## 来源

只处理合法取得的公开或授权资料：论坛与社区、视频评论、创作者内容、产品评价、客服记录。走官方接口、授权导出或人工证据包，不绕过登录或平台限制。

公开评论只是研究信号，**不**带来营销邮件、社区邀请、短信、私信或用户内容复用的许可。

## 状态顺序

```text
原始线索 → 已核对观察 → 重复问题 → 已确认洞察 → 已送达 → 关闭／驳回
```

## 每一步做什么

1. **导入原始线索。** 每条至少有：来源、链接、原话。其他格式先转成这个格式。原话一字不改地保存。
2. **人工核对。** AI 可以建议标签：车型或型号、产品、场景、问题、动机、用户原话里的说法、是否紧急。人工确认后才成为“已核对观察”；不成立的标为驳回。
3. **聚类成重复问题。** 把相似的已核对观察归成一个候选，写标题和一句摘要。
4. **确认重复问题的门槛。** 默认需要 **3 个独立声音、至少来自 2 个来源**。这是操作门槛，不是统计结论。安全、适配、产品损坏类问题可以单条紧急升级，但仍需人工核对。
5. **提升为洞察。** 人工确认后进入“已确认洞察”。不要把 AI 打的标签直接当成洞察。
6. **送到具体事项。** 可送往：FAQ、调研问题、社区话题、产品反馈、客服反馈、内容选题、官网文章候选。写清负责人和理由。
7. **跟进处理状态。** 查看已送达事项是被采纳还是被驳回，然后关闭。

## 什么时候停

来源不明、许可不清、数据无效或校验失败：停止，不继续往下推。

## 不要做

- 自动联系用户、自动发布内容。
- 把 AI 标签升级为已确认洞察。
- 导出未经批准的行动。
- 把“很多人在说”写成统计结论；写清实际核对了几条、来自哪些来源、时间范围。

## 汇总片段模板

```text
本周核对：N 条线索 → M 条已核对观察
新确认的重复问题：
- 问题标题（独立声音数 / 来源数）：一句话摘要 → 送往：FAQ / 产品反馈 …
紧急单条：
- ……（已交给：……）
仍在观察：
- ……（还差几个独立声音或来源）
```
