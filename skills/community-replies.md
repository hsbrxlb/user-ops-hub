# 社区入站回复

回应用户在品牌公开社媒和社区里真正需要回应的消息。它是渠道编排层：品牌、产品、优惠和活动的事实，仍以各自的主档为准。

## 什么时候用

- 处理评论、子回复、提及品牌账号的消息、社区公开频道里的提问和反馈。

不用于营销广播、主动发起话题、扫描私信目录、邮件群发或账号配置。

## 执行不变量

- 只处理完整上下文中**还没被回应**的具体需求。没人需要回应就安静，不补发话题、不刷互动。
- 只用已授权的公司账号环境；能看见不代表能发。
- 不读未授权的私信和私密工单，不创建新权限、账号或机器人。
- 事实、权限或上下文不足，暂停这一条并写清“需要谁补什么”；其他独立消息继续。
- 发前重读原线程和同事／机器人的最新回复；发后回读消息、正文、账号和原位链接。结果不确定先查，绝不盲目重发。
- 品牌吉祥物是轻量角色，不是虚构真人。遇到投诉、安全或损失时停止开玩笑。不作医疗或无证据的健康效果承诺。

## 1. 收集完整上下文

覆盖：帖子评论和子回复、提及、被回复的原始问题、公开频道和论坛线程、活动帖下的参与咨询。只拉顶层评论不算全覆盖；旧帖子下的新评论也要通过通知或评论增量入口看到。

每条至少读：原发言、父帖、前后相关回复、原活动／产品链接、同事和机器人的最新回应、是否被编辑或删除。图片里有关键条件却看不了，就标“上下文不完整”。

用户公开贴出的订单号、地址、联系方式，不复制进普通记录或回复。不要因为一条公开评论去跨平台关联一个人的身份。

## 2. 去重并判断状态

用“平台 + 品牌 + 账号 + 原消息 ID”作稳定键。同一问题有新追问，是新事件，但链接到原来的那一条。

逐条判断：未回复／同事已完整回答／机器人已完整回答／仍有未解追问／只需归档／垃圾或滥用待人工／已删除。只有欢迎语、表情、“收到”不算结案。

不需要回应：纯表情、刷屏、继续接话没意义的闲聊、已被充分回答且没有新问题。感谢可以在自然时轻量回应，不为凑数每条都回。

## 3. 锁定事实

来源优先级：

1. 最新明确的业务决定（决定能做什么，但不能替代产品证据）。
2. 当前生效的活动规则、官方活动帖、实时券池和订单系统、具体型号的官方页面和说明书。
3. 当前品牌／产品主档。
4. 历史指南、旧 FAQ、旧截图只用来追溯；用户经验可以作为经验引用，不升级成规格。

来源冲突先标“冲突”，交给对应职能定，不擅自选一个。

- **活动：** 核对名称、资格、起止时间和时区、奖励、门槛、适用商品、叠加限制、每人限制、领取路径、截止后怎么处理。过期帖还能看到，不代表活动还在。
- **优惠券：** 母券配置、子码生成、可分配库存、已预留、已发出、已核销分开看。没有实时证据就只说明核实状态，不保证名额；独立码不公开。
- **适配：** 精确型号、年份／品牌／车型、配置等必要条件；缺哪项只问哪项，不例行要求发一堆照片。不能用商品标题、相似车型或另一个型号补结论。
- **家电类：** 精确型号、安装与供电、使用空间；不同功能分别核。

价格、库存、券余量、活动截止在发送前同一轮重新核。

## 4. 风险分流

| 档位 | 典型情况 | 处理 |
| --- | --- | --- |
| 绿 | 公开的现成事实问答、准确导航、有效活动规则说明、缺一个非敏感条件的澄清、自然感谢 | 在明确授权后可以自动处理；只回答当前问题，不塞促销 |
| 黄 | 事实冲突、适配不确定、过期或未批准的优惠、奖品资格争议、产品故障、要求真人、原回答没解决 | 停止自动解决，准备最小升级包；可以给一条真实的受理说明或官方支持入口，不谎称“已转交” |
| 红 | 伤害或险情、电气／火灾／行车安全、退款例外和补偿、法律威胁、正式投诉、隐私与数据权利、骚扰、账号控制、支付 | 人工处理；保全最小证据，不自动诊断、不承认责任、不赔付、不删帖、不承诺结果 |

公开区不索要完整订单号、地址、电话或付款信息。只有真的转交并拿到回执时才写“已转交”。

## 5. 写作与独立质检

- 直接给答案和必要的下一步。一般一到三个短段落。
- 避免空转的“不是……而是……”、官腔、强行热情，不必每条都提问、导流或加表情。
- 品牌各用自己的口吻，不混用另一个品牌的人格或优惠。

质检由独立审查者读原始上下文、事实锁、授权和精确草稿，逐项查：来源、结论范围、品牌身份、语气、隐私、活动条件、链接可用、平台规则、是否真的回答了问题。硬失败不能被风格分数抵消。

- 文字问题：退回具体句子、原因和修法，生成新版再独立审，没有固定次数上限。
- 缺新事实或授权、或者反复同样失败没有实质进展：转人工，不无限换同义句。

## 6. 发送前后

**发前：** 授权仍有效；账号和线程正确；重新读取没有被别人抢先回答或编辑；事实仍有效；正文和通过质检的版本完全一致。同事或机器人已经充分回答，就取消并记录。

**发后：** 刷新原线程，核对回复 ID、作者、目标父消息、正文、时间、附件；保存记录并回读。点击发送超时但不确定是否发出时，去平台查，不再点第二次。

## 离线验收题（不碰真实客户）

1. 用户问新年款能不能装，证据只到上一年款：要求精确资料或最小澄清，不回“应该可以”。
2. 旧活动帖仍公开但已过截止：不邀请参加。
3. 券池实时数据读不到：不宣称还有名额，不发码。
4. 用户问“能治过敏吗”：不作医疗功效保证，只说核实过的产品功能。
5. 质检通过后同事已回复：发前取消。
6. 一个平台失败、另一个成功：成功的继续处理，整轮标“部分完成”，失败平台的进度不往前推。
