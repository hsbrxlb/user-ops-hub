# 高保真网页翻页书

## 什么时候用

- 做“翻页书”、Flip Book、可翻页的画册或刊物。
- 修这类缺陷：页面叠成一列、拖动时选中了文字、封面像硬板、翻到最后一页自动跳走、用滚动页冒充翻页。

不用于普通网站、轮播图、PDF 和幻灯片。

## 核心决定

- 用完整的软页渲染器。一个 `rotateY` 动画不是软页翻动。
- 首页列了几本书，每一本都必须能进入翻页书。
- 默认每一页都是软的，包括第一页和最后一页。不自己发明硬封面、衬页或特殊的合书动画，除非明确要求实体封面效果。
- 翻到或翻过最后一页，绝不自动返回、关闭或跳转。只能通过“返回”或 Esc 这类明确操作回到目录。
- 多本书的目录保持极简：只放书的预览和必要控件，不加展览标题、说明文字、卡片图注、状态标签或页脚提示。
- 卷角方向交给渲染器：向前翻只在右页的外侧右角，向后翻只在左页的外侧左角。靠书脊的两个角永远不能看起来可拖。
- 不要给每一页都叠一个固定在右下角的三角装饰：页面被渲染到左边时它就错了。
- 出现未绑定、直接显示出来的原始页面，是阻断故障，不是“加载中”。
- 构建和类型检查通过，不能替代真实的交互和视觉检查。

## React + StPageFlip 的实现要点

（page-flip 与 react-pageflip 均为 MIT 许可。）

**初始化关口：** 绑定成功的书必须恰好有一个 `.stf__block`、一个 `.stf__parent`，页面子元素带 `.stf__item`。在这之前：

- 隐藏原始书页根节点；
- 显示一句简短的“装订中”状态；
- 最多用新的 key 重新挂载两次；
- 永远不把原始页面列表露出来。

开发模式的 StrictMode 可能暴露重复初始化问题，本地优先不用 StrictMode 挂载，除非新版本证明清理安全。

**指针规则：**

- 书面 `user-select: none`，书里的图片 `-webkit-user-drag: none`。
- 装饰层 `pointer-events: none`。
- 按钮、链接、输入框恢复正常交互，并在这些控件上阻止 mousedown／touchstart 冒泡。
- 引擎根节点的祖先不要加 transform，因为它用 `getBoundingClientRect` 计算指针位置。

**材质设置：**

```js
{
  drawShadow: true,
  showPageCorners: true,
  showCover: false,        // 除非明确要求硬封面
  usePortrait: true,
  mobileScrollSupport: false
}
```

## 验收清单

1. 每本承诺的书都有一个 `.stf__block`，看得见的未绑定页面为零。
2. 右页只预览外侧右角，左页只预览外侧左角。
3. 靠书脊的两个角平整，没有光泽、斜线或可拖暗示。
4. 合法的卷角会产生多边形裁切和内外阴影。
5. 从右下拖到左上、从左下拖到右上，前后翻页都生效，且浏览器没有选中任何文字。
6. 刷新并进入同一本书三次，没有页面叠加。
7. 翻到最后一页并操作，书保持打开，网址不变。
8. 目录和书的舞台上没有多余标题、图注、状态文字或页脚说明。
9. 检查桌面、390×844、390×500，Chromium 和 WebKit，以及控制台输出。
10. 有用户的投诉截图时，用它做视觉审查的基线。

用真实的鼠标按下、分步移动、松开来测，不要只调 API。

## 边界

采用外部代码前先审许可证和来源；不复制没有许可的示例仓库；没有单独授权不部署、不发布、不连接生产服务。
